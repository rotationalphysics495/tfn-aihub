risks:
  - Supabase .in_() with empty list: If action_items has no asset_ids (empty list), calling .in_("asset_id", []) may produce unexpected SQL or an error in some Supabase client versions. MITIGATION: Guard the fetch_active_action_plans() call with an early return of ([], []) if asset_ids is empty. Add this check at the top of the method before any Supabase calls.
  - DATA_TEMPLATE_DEFAULT backward compatibility for custom env templates: Users who set SMART_SUMMARY_DATA_TEMPLATE env var with a custom template won't have the {action_plan_data} placeholder. MITIGATION: The existing try/except KeyError fallback pattern at lines 364-370 already handles missing placeholders — extend it to also append action plan data. The backward compat logic will try template.format(**format_values), and if KeyError occurs due to missing {action_plan_data}, pop the key and append it as a standalone section.
  - Existing test breakage from SYSTEM_PROMPT_DEFAULT changes: The test file test_smart_summary_trend_context.py imports SYSTEM_PROMPT_DEFAULT and checks for specific instruction text (e.g., "trend" keyword). Adding new numbered instructions could shift existing instruction numbering. MITIGATION: Don't renumber existing instructions — add new instructions as 8 and 9 after the existing instruction 7. Verify existing trend context tests still pass after the change.
  - action_plans table may not exist in all environments: Some dev/test environments might not have run migration 0034. MITIGATION: The try/except pattern in fetch_active_action_plans() returns ([], []) on any exception, including "relation does not exist" errors from PostgreSQL. The isolated try/except in build_context() provides a second safety net.
  - Performance: Two additional Supabase queries per summary generation. MITIGATION: Both queries are filtered by asset_id (indexed via idx_action_plans_asset_id) and status (indexed via idx_action_plans_status), so they should be fast. The verified_at query also benefits from the status index. For a typical plant with <20 assets and <50 action plans, query times should be negligible (<50ms each).
  - Prompt template size increase: Adding the ACTION PLAN STATUS section increases the data prompt size. MITIGATION: The section is bounded by the number of action plans per asset (typically 0-3), so the increase is minimal (likely <200 tokens). The existing token estimation and monitoring will capture any increase.
